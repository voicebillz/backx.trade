# SEO + AI SEO for gazz.fun

gazz.fun is a Vite SPA on Vercel. Crawlers that don't run JS (X, Discord,
Telegram, many AI crawlers) only see the static HTML, so SEO lives in FIVE
places that must agree. Treat them as one unit: change one → check all.

| Surface | File | What it does |
|---|---|---|
| Runtime tags | `web/src/lib/seo.ts` (`ROUTE_SEO`, `DEFAULT_SEO`, `OG_VER`) | title / description / canonical / OG / Twitter tags on client-side navigation |
| Prerendered tags | `web/scripts/prerender-seo.mjs` (`ROUTES`) | post-build: copies `dist/index.html` → `dist/<route>/index.html` with route tags stamped in (Vercel serves real files before the SPA rewrite). Runs in `npm run build`. |
| Sitemap | generated by `prerender-seo.mjs` → `dist/sitemap.xml` | pages + live coins + live funds + predict markets (`/api/predict/sitemap.xml`) |
| Crawler policy | `web/public/robots.txt` | allows all, EXPLICITLY welcomes GPTBot, OAI-SearchBot, ClaudeBot, PerplexityBot, Google-Extended; points at the sitemap |
| AI summary | `web/public/llms.txt` | the plain-text brief LLMs read: what gazz.fun is, products, key pages, APIs, contacts |
| Structured data | `web/index.html` `application/ld+json` | Organization (logo, sameAs: X, Discord, GitHub) + WebSite |
| Share cards | `web/public/og/og-*.png` (served via `api.gazz.fun/api/brand/og/...?v=OG_VER`) | 1200×630 preview images per section |

## Rules

1. **Route tables stay in sync.** A route added to `ROUTE_SEO` gets the same
   title/description/image in `prerender-seo.mjs` `ROUTES` (and vice versa).
   No route ships without both, or its link preview shows the home card.
2. **Titles:** `<Specific name> — <benefit> | gazz.fun`, under ~60 chars.
   Descriptions: one concrete sentence, 120–160 chars, real facts only, no
   hype words, no price promises. Lead with what the page lets you DO.
3. **OG images:** 1200×630, the dark clean card style (v7), max ~6 words of
   copy, readable at 400 px wide. After changing ANY card, bump `OG_VER` in
   `seo.ts` so X/Discord refetch. Follow the marketing-image skill.
4. **Facts drift — llms.txt is the first casualty.** Whenever a product number
   or mechanism changes (fund count/classes, fee %, holder splits, chains,
   new product, retired product), update `llms.txt` in the same change. Prefer
   durable phrasing ("40+ funds across three classes") over exact counts that
   go stale. Never state an unconfirmed listing/partnership/audit. 2026-11-01:
   fixed "230 funds" → "40+ funds in three classes (incl. Fixed Income)".
5. **Retired products leave every surface** (route tables, sitemap, llms.txt,
   OG cards) — e.g. the NFT launchpad/marketplace and the old oracle are
   SCRAPPED; GAZZ TANKS lives on.
6. **Never break the locked endpoints**: GeckoTerminal token-info + logo URLs
   (CLAUDE.md, 2026-10-13) and the CoinGecko feed `/api/chain/4663/{token}`.

## AI SEO (GEO): how to get cited by AI answers

AI engines quote pages that state clear, checkable facts in plain language.
- **Answer-shaped copy:** Docs/FAQ sections that answer the questions people
  actually ask ("What is GUSD?", "How do gazz.fun holders get paid?", "Is the
  LP locked?") in the first sentence, then the detail. One fact per sentence,
  numbers with units, names spelled the same everywhere ($GAZZ, GAZZ TANKS,
  GazzPad, GUSD, Robinhood Chain, chain id 4663).
- **Entity consistency:** the same one-line definition of gazz.fun in
  llms.txt, the JSON-LD WebSite description, the X bio, Discord and GitHub
  README. Same `sameAs` links everywhere.
- **Crawlable proof:** keep Docs, Audit and the contract tables server-visible
  (prerendered routes), with contract addresses as text, not images.
- **llms.txt structure:** title → one-paragraph summary → "What it does"
  (one bullet per product, live/status stated) → "Key pages" → "APIs" →
  contacts. Keep it under ~150 lines, no marketing adjectives.
- **Fresh signals:** a product launch = route entry + OG card + sitemap entry
  (automatic) + llms.txt bullet + Docs section + an X post linking it (first
  reply). AI engines pick up what is consistent across sources.
- **Don't block:** never disallow the AI crawlers in robots.txt.

## Ship checklist (new page or changed product)
- [ ] `seo.ts` ROUTE_SEO entry + matching `prerender-seo.mjs` ROUTES entry
- [ ] OG card in `web/public/og/` (+ `OG_VER` bump if an existing card changed)
- [ ] `llms.txt` bullet / numbers updated; retired things removed
- [ ] Docs section with answer-first copy (UI rule: short intros on pages, detail in Docs)
- [ ] JSON-LD still valid (only touch when the org/site identity changes)
- [ ] After deploy: `curl -s https://www.gazz.fun/<route>/ | grep og:` shows the route's tags; `https://www.gazz.fun/sitemap.xml` lists it
